# KV-Cache 分叉对比

给推理工程师的小工具：从一次推理的中途分叉出多条分支，各自续写不同词元，
对比下一词元预测。内置固定权重的单层因果注意力小模型，续写复用实际算出的
KV 缓存；KV 按固定大小的物理块管理，分叉共享前缀块（写时复制），块数有上限，
网页实时显示块占用。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

不用 Docker 也可以：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

可调参数（环境变量，compose.yaml 里有默认值）：

| 变量 | 默认 | 含义 |
|---|---|---|
| `VOCAB_SIZE` | 64 | 词表大小，词元取值 `0..63` |
| `D_MODEL` | 32 | 注意力维度 |
| `BLOCK_SIZE` | 4 | 每个物理块容纳的词元数 |
| `NUM_BLOCKS` | 32 | 物理块总数（全部会话共享的容量上限） |
| `SEED` | 1234 | 固定权重的伪随机种子 |
| `SPILL_DIR` | `./spill` | 暂停到磁盘时 KV 快照的存放目录 |

## 用法

1. 输入一串整数词元建会话（自动算出 KV 并写入块）；
2. 选中一条分支，在任意位置（包括块中间）分叉 —— 只共享前缀块、不新占块，池满也能分叉；
3. 给各分支追加一串词元，页面展示各自的下一词元预测（top-1 与 top-5）；
4. 关闭分支只回收引用计数归零的块；页头与块网格实时显示占用；
5. 会话卡片标题旁的「暂停到磁盘」把整个会话的 KV 写成本地文件并释放它占的块；
   「从磁盘恢复」读回文件、重新占用块并继续续写。

## 暂停与恢复（KV 落盘）

暂停是**会话级**的，按请求分三段，只有第一段和第三段持有引擎锁：

1. **拍快照**（锁内）：复制会话全部分支的词元表与逻辑块表，并按物理块 id 去重
   复制实际 K/V —— 共享块在文件里只存一份；
2. **写文件**（锁外）：写到临时文件，`fsync` 后 `os.replace` 原子替换，读者只会看到
   完整文件；期间其他会话照常追加/分叉/预测，本会话也仍可操作；
3. **提交**（锁内）：比较会话的 `revision` 与拍快照时是否一致、分支集合是否变化。
   不一致就**作废本次暂停**、删掉刚落盘的文件、**一个块都不释放**；
   只有文件写好且会话未变，才把会话标为 `paused` 并释放其全部块。

恢复同样把 I/O 放在锁外：先读文件、校验结构/摘要/模型配置，再在锁内一次性
检查空闲块并分配、按文件里的唯一块引用重建共享块表（引用计数还原），
并逐一核对恢复后的预测与文件内 K/V 算出的预测一致后才提交。
提交前任何一步失败（块不足、文件损坏、配置不符）都会整体回滚：
**会话保持暂停、不占块**，页面展示具体原因，修复后可原样重试。

文件格式为单个 `.npz`：`meta`（JSON，分支 id/名称/词元/块引用、模型配置）+
`K`/`V`（唯一块数组）+ SHA-256 摘要。恢复后分支 id、共享关系与预测保持不变，
原分支可直接继续追加续写。

> 暂停/恢复状态只保存在进程内存里，暂存文件供本次服务运行内恢复；
> 进程重启后文件不会自动重建会话（见「余项」）。compose 里用命名卷
> `spill-data` 把 `/app/spill` 挂出来，容器重启不丢文件。

## 设计要点

- **模型**（`app/model.py`）：单层单头因果注意力，`x = E[tok] + P[pos]`，
  `k/v/q = x @ W_{k,v,q}`，`logits = softmax(Kq/√d)·V @ Wo`。权重由固定种子生成，
  float64。K/V 只取决于 `(token, position)`，因此缓存值与从头逐位计算完全等价。
- **块池**（`app/blocks.py`）：固定数量物理块，每块 `BLOCK_SIZE` 个槽位，
  引用计数管理共享；归零才回到空闲池。
- **引擎**（`app/engine.py`）：
  - 分叉：子分支引用前缀块并增加引用计数，不分配新块；
  - 追加：先算清所需块数（末尾共享未满块需写时复制 1 块 + 新增整块数），
    空闲不足则整体拒绝，分支内容与块占用不变；检查与提交在同一把锁内完成，
    并发追加安全；
  - 分叉点落在块内时，子分支只承认该块前 `position` 个槽位，首次写入触发写时复制；
  - 预测只读缓存的 K/V（加上末词元的 q），不重算历史；
  - 暂停/恢复的三段式流程见上，I/O 始终在锁外。
- **快照文件**（`app/spill.py`）：唯一块去重、原子写入、SHA-256 + 结构校验，
  所有损坏/配置不符都转成带中文原因的 `SpillCorruptError`。
- **API**（`app/main.py`）：`POST /api/sessions`、`POST /api/sessions/{id}/fork`、
  `POST /api/sessions/{id}/append`、`GET /api/sessions/{id}/branches/{bid}/predict`、
  `DELETE /api/sessions/{id}/branches/{bid}`、`DELETE /api/sessions/{id}`、
  `POST /api/sessions/{id}/pause`、`POST /api/sessions/{id}/resume`、
  `GET /api/stats`。容量不足、暂停冲突、文件损坏都返回 409（响应里的 `reason`
  区分 `capacity` / `conflict` / `spill`），参数非法 400，不存在 404。

## 测试

```bash
pip install -r requirements-dev.txt
pytest -v
```

覆盖：缓存路径 vs 从头计算的 logits 一致（1e-10）、块内分叉的共享与写时复制、
满池分叉、追加整体拒绝的原子性、关闭分支的精确回收、引擎内与 HTTP 层的并发容量约束；
以及暂停/恢复：共享块去重、写盘期间续写/关分支作废暂停且不释放块、
写盘失败保持原状、恢复争用块不足时保持暂停可重试、损坏/配置不符/截断文件、
恢复与并发分配竞争、I/O 期间其他会话可响应、恢复后续写与从头计算一致。
